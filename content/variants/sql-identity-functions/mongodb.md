# Expected Answer (MongoDB 7.0/8.0)

MongoDB uses `_id` as the primary key for every document. If not provided, MongoDB automatically generates an **ObjectId**.

-   **ObjectId**: A 12-byte identifier consisting of a 4-byte timestamp, a 5-byte random value, and a 3-byte incrementing counter.
-   **Client-Side Generation**: Unlike relational databases where the DB generates the ID, MongoDB drivers can generate the `ObjectId` before the insert happens.

# Why It Matters

ObjectIds are designed to be globally unique across a distributed cluster without requiring a central authority to coordinate ID generation. This is key to MongoDB's horizontal scalability.

# Example

```javascript
// Generated by the driver or DB
const newId = new ObjectId();
db.collection.insertOne({ _id: newId, name: "Alice" });
```

# Common Mistakes

- **Assuming sequential IDs**: While ObjectIds are generally increasing because of the timestamp prefix, they are not strictly sequential like an integer identity.
- **Overwriting _id**: If you use a custom `_id` (like a username), you must ensure uniqueness yourself; MongoDB will not generate a replacement if your custom ID collides.

# Follow-up Questions

- **Can you use a UUID for _id?** (Answer: Yes, MongoDB supports UUIDs as a BSON type).
- **What is the advantage of client-side ID generation?** (Answer: It allows the application to know the ID before the data is even sent to the database).
