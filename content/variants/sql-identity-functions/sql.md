# Expected Answer

SQL Server provides three main ways to get the last identity value, differing by **Scope** and **Session**:

1.  **SCOPE_IDENTITY()**: Returns the last identity value generated in the **current session** and **current scope** (same stored procedure, trigger, or batch). **This is the recommended method.**
2.  **@@IDENTITY**: Returns the last identity value generated in the **current session**, regardless of scope. If a trigger on the table inserts into another table with an identity column, `@@IDENTITY` returns the value from the trigger's table.
3.  **IDENT_CURRENT('TableName')**: Returns the last identity value generated for a **specific table** in **any session** and **any scope**.

# Why It Matters

Using `@@IDENTITY` instead of `SCOPE_IDENTITY()` is a common source of bugs. If someone adds a logging trigger to a table that also has an identity column, your code might start receiving the "LogID" instead of the "OrderID" you were expecting.

# SQL Example

```sql
-- Recommended Usage
INSERT INTO Orders (OrderDate) VALUES (GETDATE());
SELECT SCOPE_IDENTITY() AS NewOrderID;

-- Comparison Scenario
-- If a trigger on 'Orders' inserts into 'AuditLog'...
-- SCOPE_IDENTITY() = New Order ID
-- @@IDENTITY = New AuditLog ID
```

# Common Mistakes

- **Using @@IDENTITY by default**: It's dangerous because it's not scope-safe.
- **Using IDENT_CURRENT in multi-user environments**: Since it returns the last ID from *any* session, you might get an ID generated by another user who happened to insert a millisecond after you.

# Follow-up Questions

- **What is a "Scope" in SQL Server?** (Answer: A module like a stored procedure, trigger, function, or batch).
- **What happens if an INSERT fails?** (Answer: The identity value is still consumed; the next successful insert will have a gap).
