# Expected Answer (PostgreSQL 16)

PostgreSQL handles identity values using `RETURNING` or sequences.

1.  **RETURNING clause**: `INSERT ... RETURNING id`. Scope-safe and session-safe.
2.  **currval('sequence_name')**: Last value generated for a sequence in the current session.
3.  **lastval()**: Last value generated by any sequence in the current session.

# Why It Matters

Using `RETURNING` is the most efficient and robust way to retrieve generated keys in PostgreSQL 16. It avoids extra network round-trips and is completely safe from concurrency issues or trigger side-effects.

# SQL Example

```sql
-- Recommended: RETURNING
INSERT INTO users (name) 
VALUES ('Alice') 
RETURNING id;

-- Using sequences explicitly
INSERT INTO users (name) VALUES ('Bob');
SELECT currval(pg_get_serial_sequence('users', 'id'));
```

# Common Mistakes

- **Using lastval() blindly**: If your session performs an insert into a different table (perhaps via a trigger), `lastval()` will return that new value, not the one you expected.
- **Forgetting sequence names**: `currval` requires the exact sequence name, which can be tricky if using `SERIAL` columns (use `pg_get_serial_sequence`).

# Follow-up Questions

- **Difference between SERIAL and IDENTITY?** (Answer: `IDENTITY` is SQL-compliant; `SERIAL` is a Postgres-specific macro).
- **Is currval session-safe?** (Answer: Yes).
